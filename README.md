# Oudh Sannai Business

Saya ingin membangun sebuah aplikasi ERP (Enterprise Resource Planning) berbasis web yang terinspirasi dari sistem Accurate Online. Nama aplikasi: Oudh Sannai Business Management System Tujuan: Membangun sistem manajemen bisnis terintegrasi yang mencakup: 1. Penjualan 2. Pembelian 3. Persediaan (Inventory) 4. Keuangan (Accounting) 5. Laporan (Reporting) Aplikasi harus memiliki desain profesional, modern, responsif, mudah digunakan, dan memiliki fondasi database yang kuat. JANGAN MEMBUAT SISTEM HANYA SEBAGAI MOCKUP ATAU DEMO STATIS. Bangun fitur dengan database, validasi, business logic, dan relasi antar modul yang dapat digunakan secara nyata. Gunakan desain yang terinspirasi dari software ERP profesional tanpa menyalin merek, aset, atau implementasi proprietary Accurate. ================================================== 1. TEKNOLOGI DAN ARSITEKTUR ================================================== Gunakan teknologi yang tersedia dan sesuai dengan platform Lovable. Prioritas: - React - TypeScript - Tailwind CSS - Komponen UI profesional - Supabase untuk database dan autentikasi jika tersedia - PostgreSQL - Row Level Security (RLS) - Relasi database yang terstruktur - Validasi frontend dan backend - Transaction-safe business logic Pastikan semua operasi yang memengaruhi stok, saldo, dan jurnal memiliki validasi serta integritas data. Gunakan pendekatan modular sehingga setiap fitur dapat dikembangkan dan dipelihara secara terpisah. ================================================== 2. DESAIN UI/UX ================================================== Buat tampilan ERP profesional dengan karakteristik: - Sidebar navigasi di sebelah kiri - Header dengan nama perusahaan dan profil user - Dashboard yang informatif - Layout responsif desktop dan tablet - Tabel data dengan pagination - Search dan filter - Form input yang terstruktur - Modal konfirmasi untuk tindakan penting - Toast notification - Loading state - Empty state - Error state - Skeleton loading jika diperlukan - Dark mode jika mudah diimplementasikan - Bahasa antarmuka Indonesia - Format mata uang Rupiah (IDR) Gunakan desain yang bersih, profesional, dan konsisten. Hindari tampilan yang terlalu ramai. Gunakan komponen yang reusable untuk: - Tabel - Form - Button - Modal - Dropdown - Date picker - Currency input - Status badge - Pagination - Filter ================================================== 3. AUTHENTICATION DAN USER MANAGEMENT ================================================== Buat sistem autentikasi dan otorisasi. Fitur: - Login - Logout - Session management - User profile - Role-based access control - Permission management - Password reset jika didukung Role default: 1. Super Admin 2. Admin 3. Sales 4. Purchasing 5. Warehouse 6. Finance 7. Accounting 8. Manager 9. Auditor Setiap role memiliki permission berbeda. Permission minimal: - View - Create - Edit - Delete - Approve - Post - Cancel - Export Pastikan user tidak dapat mengakses data atau tindakan yang tidak diizinkan. Gunakan RLS dan validasi server-side jika Supabase digunakan. ================================================== 4. MASTER DATA ================================================== Buat modul Master Data. Menu: - Produk - Kategori Produk - Satuan - Pelanggan - Supplier - Gudang - Akun Keuangan - Pajak (opsional untuk fase awal) - Pengaturan Perusahaan ------------------------- 4.1 MASTER PRODUK ------------------------- Field: - ID - SKU - Nama Produk - Kategori - Satuan - Harga Beli - Harga Jual - Minimum Stok - Tipe Produk - Status Aktif/Nonaktif - Deskripsi - Created At - Updated At Fitur: - Tambah produk - Edit produk - Lihat detail produk - Nonaktifkan produk - Search - Filter - Pagination SKU harus unik. Validasi: - Nama wajib diisi - SKU wajib unik - Harga tidak boleh negatif - Satuan wajib dipilih - Produk yang sudah digunakan dalam transaksi tidak boleh dihapus secara sembarangan ------------------------- 4.2 MASTER CUSTOMER ------------------------- Field: - Customer Code - Nama - Nomor Telepon - Email - Alamat - NPWP jika diperlukan - Limit Kredit (opsional) - Status - Saldo Piutang (derived) Fitur CRUD, search, filter, dan detail riwayat transaksi. ------------------------- 4.3 MASTER SUPPLIER ------------------------- Field: - Supplier Code - Nama Supplier - Nomor Telepon - Email - Alamat - NPWP jika diperlukan - Status Fitur CRUD, search, filter, dan riwayat pembelian. ------------------------- 4.4 MASTER GUDANG ------------------------- Field: - Warehouse Code - Nama Gudang - Alamat - Status Dukung lebih dari satu gudang. ================================================== 5. MODUL PENJUALAN ================================================== Buat modul Penjualan yang terintegrasi dengan Inventory, Piutang, Accounting, dan Reporting. Menu: - Sales Order - Delivery Order - Sales Invoice - Retur Penjualan - Penerimaan Pembayaran - Laporan Penjualan ------------------------- 5.1 SALES ORDER ------------------------- Field Header: - Nomor Transaksi - Tanggal - Customer - Gudang - Status - Catatan - Subtotal - Diskon - Pajak jika diaktifkan - Grand Total Field Item: - Produk - Deskripsi - Kuantitas - Satuan - Harga - Diskon - Total Fitur: - Create - Edit draft - View detail - Confirm - Cancel sesuai aturan - Search - Filter tanggal - Filter customer - Filter status Validasi: - Customer wajib dipilih - Minimal satu item - Kuantitas harus lebih besar dari 0 - Produk harus aktif - Harga dan diskon harus valid ------------------------- 5.2 DELIVERY ORDER ------------------------- Buat fitur pengiriman barang berdasarkan Sales Order. Fitur: - Membuat Delivery Order - Pengiriman sebagian - Pengiriman penuh - Memilih gudang - Validasi ketersediaan stok - Status pengiriman - Riwayat pengiriman Pastikan stok berkurang berdasarkan kebijakan pengeluaran barang yang ditetapkan. Jangan mengurangi stok berulang kali akibat duplikasi atau pengulangan proses. ------------------------- 5.3 SALES INVOICE ------------------------- Fitur: - Membuat invoice dari Sales Order atau transaksi yang sesuai - Invoice tunai - Invoice kredit - Jatuh tempo - Diskon - Pajak jika diaktifkan - Status pembayaran - Print invoice - Export PDF jika didukung Status: - Draft - Confirmed - Partially Paid - Paid - Cancelled Invoice kredit harus membentuk piutang sesuai aturan akuntansi. Hindari duplikasi invoice untuk transaksi yang sama. ------------------------- 5.4 CUSTOMER PAYMENT ------------------------- Fitur: - Penerimaan pembayaran customer - Pembayaran sebagian - Pelunasan invoice - Alokasi pembayaran ke invoice - Metode pembayaran - Akun kas/bank - Nomor referensi - Tanggal pembayaran Validasi: - Jumlah pembayaran harus valid - Tidak boleh mengalokasikan pembayaran melebihi saldo invoice tanpa aturan khusus - Saldo piutang diperbarui secara konsisten ------------------------- 5.5 RETUR PENJUALAN ------------------------- Fitur: - Membuat retur dari invoice - Memilih item dan kuantitas - Alasan retur - Persetujuan retur - Penyesuaian stok - Penyesuaian piutang atau pembayaran - Jurnal koreksi jika diperlukan Dukung aturan kondisi barang yang dikembalikan. ================================================== 6. MODUL PEMBELIAN ================================================== Buat modul Pembelian yang terintegrasi dengan Inventory, Hutang, Accounting, dan Reporting. Menu: - Purchase Order - Goods Receipt - Purchase Invoice - Retur Pembelian - Pembayaran Supplier - Laporan Pembelian ------------------------- 6.1 PURCHASE ORDER ------------------------- Field: - Nomor PO - Tanggal - Supplier - Gudang - Status - Catatan - Item - Kuantitas - Harga - Diskon - Total Fitur: - Create - Edit draft - Confirm - Cancel sesuai aturan - Search - Filter - Detail transaksi ------------------------- 6.2 GOODS RECEIPT ------------------------- Fitur: - Penerimaan barang berdasarkan Purchase Order - Penerimaan sebagian - Penerimaan penuh - Kuantitas diterima - Gudang - Tanggal penerimaan - Catatan - Validasi kuantitas Barang yang diterima harus menambah stok sesuai aturan transaksi. Pastikan penerimaan barang tidak tercatat dua kali secara tidak sengaja. ------------------------- 6.3 PURCHASE INVOICE ------------------------- Fitur: - Membuat invoice pembelian - Menghubungkan dengan penerimaan barang jika diperlukan - Pembelian tunai atau kredit - Jatuh tempo - Diskon - Pajak jika diaktifkan - Status pembayaran Invoice kredit harus membentuk hutang sesuai aturan akuntansi. Dukung invoice yang diterima setelah barang diterima. ------------------------- 6.4 SUPPLIER PAYMENT ------------------------- Fitur: - Pembayaran supplier - Pembayaran sebagian - Pelunasan - Alokasi pembayaran ke invoice - Metode pembayaran - Akun kas/bank - Nomor referensi - Tanggal pembayaran Validasi: - Pembayaran tidak boleh melebihi saldo hutang tanpa aturan khusus - Saldo hutang harus diperbarui dengan benar - Jurnal pembayaran harus konsisten ------------------------- 6.5 RETUR PEMBELIAN ------------------------- Fitur: - Retur barang ke supplier - Memilih invoice atau penerimaan terkait - Kuantitas retur - Alasan retur - Penyesuaian stok - Penyesuaian hutang - Jurnal koreksi jika diperlukan ================================================== 7. MODUL PERSEDIAAN (INVENTORY) ================================================== Buat modul Inventory yang terintegrasi dengan Penjualan dan Pembelian. Menu: - Stok Barang - Kartu Stok - Mutasi Stok - Transfer Gudang - Penyesuaian Stok - Stock Opname - Valuasi Persediaan ------------------------- 7.1 STOCK BALANCE ------------------------- Tampilkan: - Produk - Gudang - Stok tersedia - Stok dipesan (opsional) - Stok minimum - Satuan - Status stok Saldo stok harus dapat ditelusuri ke mutasi. ------------------------- 7.2 INVENTORY MOVEMENT ------------------------- Setiap pergerakan stok harus memiliki: - Produk - Gudang - Tipe transaksi - Referensi transaksi - Kuantitas masuk - Kuantitas keluar - Tanggal - User - Catatan Tipe transaksi: - Opening Balance - Purchase Receipt - Sales Delivery - Sales Return - Purchase Return - Stock Adjustment - Warehouse Transfer Pastikan: - Tidak ada stok negatif jika kebijakan bisnis melarangnya - Tidak ada mutasi ganda - Mutasi dapat diaudit - Pembatalan transaksi tidak merusak saldo ------------------------- 7.3 STOCK ADJUSTMENT ------------------------- Fitur: - Penyesuaian stok - Alasan penyesuaian - Persetujuan jika diperlukan - Penambahan atau pengurangan stok - Riwayat audit Batasi penyesuaian stok berdasarkan permission. ------------------------- 7.4 WAREHOUSE TRANSFER ------------------------- Fitur: - Gudang asal - Gudang tujuan - Produk - Kuantitas - Tanggal - Status - Nomor transfer Transfer harus menjaga keseimbangan stok antar gudang. ------------------------- 7.5 STOCK OPNAME ------------------------- Fitur: - Membuat sesi stock opname - Memilih gudang - Daftar produk - Stok sistem - Stok fisik - Selisih - Alasan selisih - Persetujuan - Penyesuaian berdasarkan hasil opname ------------------------- 7.6 INVENTORY VALUATION ------------------------- Dukung metode valuasi persediaan yang dipilih pada konfigurasi sistem. Untuk MVP: - Pilih Average Cost atau FIFO - Pastikan perhitungan konsisten - HPP harus terhubung dengan transaksi persediaan - Jangan menampilkan valuasi yang tidak memiliki dasar perhitungan yang jelas ================================================== 8. MODUL KEUANGAN (ACCOUNTING) ================================================== Buat modul Accounting menggunakan konsep double-entry bookkeeping. Menu: - Chart of Accounts - Jurnal Umum - Buku Besar - Neraca Saldo - Piutang - Hutang - Kas dan Bank - Periode Akuntansi - Tutup Buku ------------------------- 8.1 CHART OF ACCOUNTS ------------------------- Buat struktur akun: - Asset - Liability - Equity - Revenue - Expense Contoh akun: 1000 Kas 1100 Bank 1200 Piutang Usaha 1300 Persediaan 2000 Hutang Usaha 3000 Modal 4000 Penjualan 5000 Harga Pokok Penjualan 5100 Beban Operasional Dukung: - Kode akun - Nama akun - Tipe akun - Parent account jika diperlukan - Status aktif - Saldo normal - Validasi kode unik ------------------------- 8.2 JOURNAL ENTRY ------------------------- Setiap jurnal harus memiliki: - Nomor jurnal - Tanggal - Deskripsi - Sumber transaksi - Status - Total debit - Total kredit - Created By - Posted By - Posted At ATURAN WAJIB: Total Debit harus sama dengan Total Kredit. Jurnal yang sudah diposting tidak boleh diedit secara bebas. Gunakan mekanisme pembatalan atau jurnal koreksi sesuai aturan. ------------------------- 8.3 AUTOMATIC JOURNAL ------------------------- Buat mekanisme pembentukan jurnal otomatis dari transaksi. Contoh: Penjualan tunai: Debit Kas Credit Penjualan Penjualan kredit: Debit Piutang Usaha Credit Penjualan Pengakuan HPP: Debit HPP Credit Persediaan Pembelian kredit: Debit Persediaan atau akun biaya yang sesuai Credit Hutang Usaha Pembayaran supplier: Debit Hutang Usaha Credit Kas/Bank Pastikan pemetaan akun dapat dikonfigurasi dan sesuai dengan jenis transaksi. Jangan membuat jurnal ganda ketika transaksi diproses ulang. ------------------------- 8.4 PIUTANG USAHA ------------------------- Fitur: - Daftar invoice belum lunas - Saldo piutang - Jatuh tempo - Pembayaran sebagian - Pelunasan - Aging piutang - Riwayat transaksi ------------------------- 8.5 HUTANG USAHA ------------------------- Fitur: - Daftar invoice supplier - Saldo hutang - Jatuh tempo - Pembayaran sebagian - Pelunasan - Aging hutang - Riwayat transaksi ------------------------- 8.6 CASH AND BANK ------------------------- Fitur: - Akun kas - Akun bank - Kas masuk - Kas keluar - Transfer antar akun - Penerimaan pembayaran - Pembayaran supplier - Riwayat transaksi Pastikan transaksi kas dan bank terhubung dengan jurnal yang relevan. ------------------------- 8.7 ACCOUNTING PERIOD ------------------------- Fitur: - Tahun fiskal - Periode akuntansi - Pembukaan periode - Penutupan periode - Validasi transaksi pada periode tertutup Transaksi tidak boleh diposting ke periode tertutup tanpa prosedur khusus yang diizinkan. ================================================== 9. MODUL LAPORAN (REPORTING) ================================================== Buat modul laporan yang mengambil data dari transaksi dan jurnal yang tervalidasi. Semua laporan harus memiliki filter: - Periode tanggal - Gudang jika relevan - Produk jika relevan - Customer jika relevan - Supplier jika relevan - Status jika relevan Dukung: - Search - Filter - Pagination jika diperlukan - Export CSV/Excel jika tersedia - Print - PDF jika didukung ------------------------- 9.1 LAPORAN PENJUALAN ------------------------- - Penjualan per periode - Penjualan per produk - Penjualan per customer - Retur penjualan - Invoice belum lunas - Ringkasan penjualan ------------------------- 9.2 LAPORAN PEMBELIAN ------------------------- - Pembelian per periode - Pembelian per produk - Pembelian per supplier - Retur pembelian - Invoice belum dibayar ------------------------- 9.3 LAPORAN PERSEDIAAN ------------------------- - Stok saat ini - Kartu stok - Mutasi stok - Stok minimum - Penyesuaian stok - Valuasi persediaan ------------------------- 9.4 LAPORAN KEUANGAN ------------------------- - Laba Rugi - Neraca - Arus Kas - Buku Besar - Neraca Saldo - Aging Piutang - Aging Hutang Pastikan laporan keuangan menggunakan data jurnal yang sudah diposting sesuai aturan sistem. Laporan harus konsisten dengan transaksi dan saldo akun. ================================================== 10. DASHBOARD ================================================== Buat dashboard utama setelah user login. Tampilkan: - Total penjualan periode berjalan - Total pembelian periode berjalan - Total piutang - Total hutang - Nilai persediaan - Ringkasan kas dan bank - Grafik penjualan - Grafik pembelian - Produk dengan stok minimum - Invoice belum lunas - Hutang mendekati jatuh tempo - Aktivitas transaksi terbaru Gunakan data aktual dari database. Dashboard harus menyesuaikan permission user. ================================================== 11. DATABASE DESIGN ================================================== Buat database relasional dengan struktur yang jelas. Tabel utama: AUTHENTICATION: - profiles - roles - permissions - user_roles - role_permissions MASTER: - companies - products - product_categories - units - customers - suppliers - warehouses - accounts SALES: - sales_orders - sales_order_items - deliveries - delivery_items - sales_invoices - sales_invoice_items - sales_returns - sales_return_items - customer_payments - customer_payment_allocations PURCHASE: - purchase_orders - purchase_order_items - goods_receipts - goods_receipt_items - purchase_invoices - purchase_invoice_items - purchase_returns - purchase_return_items - supplier_payments - supplier_payment_allocations INVENTORY: - inventory_balances - inventory_movements - stock_adjustments - stock_adjustment_items - stock_transfers - stock_transfer_items - stock_opnames - stock_opname_items ACCOUNTING: - journal_entries - journal_entry_lines - cash_accounts - cash_transactions - accounting_periods AUDIT: - audit_logs - document_status_histories Gunakan foreign key, index, unique constraint, dan validasi yang sesuai. Setiap tabel transaksi harus memiliki: - ID - Nomor dokumen jika relevan - Status - Created At - Updated At - Created By - Updated By jika diperlukan ================================================== 12. BUSINESS RULES DAN INTEGRITAS DATA ================================================== Implementasikan aturan berikut: 1. Nomor dokumen harus unik sesuai jenis transaksi dan perusahaan. 2. Total dokumen harus dihitung dari item, diskon, dan pajak sesuai konfigurasi. 3. Kuantitas dan harga tidak boleh bernilai negatif kecuali aturan khusus. 4. Stok harus diperbarui secara konsisten. 5. Saldo piutang dan hutang harus dapat ditelusuri. 6. Total debit dan kredit jurnal harus seimbang. 7. Transaksi yang sudah diposting tidak boleh diedit sembarangan. 8. Perubahan penting harus dicatat dalam audit trail. 9. User hanya dapat melakukan tindakan sesuai permission. 10. Periode tertutup harus membatasi transaksi sesuai aturan. 11. Proses yang dapat dijalankan ulang tidak boleh menghasilkan duplikasi stok atau jurnal. 12. Gunakan validasi server-side untuk operasi kritis. 13. Pastikan operasi multi-tabel yang saling terkait bersifat atomik jika memungkinkan. 14. Jangan menghapus data transaksi secara permanen tanpa kebijakan dan permission yang sesuai. ================================================== 13. AUDIT TRAIL ================================================== Buat audit trail untuk: - Create transaksi - Edit transaksi - Confirm - Approve - Post - Cancel - Payment - Stock adjustment - Perubahan master data - Perubahan permission Simpan: - User - Waktu - Aksi - Jenis dokumen - ID dokumen - Nilai sebelum perubahan jika relevan - Nilai setelah perubahan jika relevan ================================================== 14. VALIDASI DAN ERROR HANDLING ================================================== Buat validasi yang jelas pada frontend dan backend. Contoh: - Field wajib kosong - SKU duplikat - Stok tidak mencukupi - Customer tidak ditemukan - Supplier tidak ditemukan - Pembayaran melebihi saldo - Jurnal tidak seimbang - Dokumen sudah diposting - Periode sudah ditutup - User tidak memiliki permission Tampilkan pesan error yang mudah dipahami dalam bahasa Indonesia. Jangan menampilkan error teknis mentah kepada user jika tidak diperlukan. ================================================== 15. WORKFLOW TRANSAKSI ================================================== Implementasikan alur berikut. PENJUALAN: Sales Order → Delivery Order → Inventory Out → Sales Invoice → Piutang atau Kas → Jurnal → Laporan PEMBELIAN: Purchase Order → Goods Receipt → Inventory In → Purchase Invoice → Hutang atau Kas → Jurnal → Laporan RETUR PENJUALAN: Sales Return → Validasi → Inventory Adjustment jika barang diterima kembali → Penyesuaian Piutang/Kas → Jurnal Koreksi RETUR PEMBELIAN: Purchase Return → Validasi → Inventory Adjustment → Penyesuaian Hutang/Kas → Jurnal Koreksi Pastikan aturan waktu pengakuan transaksi, stok, dan jurnal didefinisikan dengan jelas. ================================================== 16. PENGUJIAN (QA) ================================================== Bangun aplikasi dengan mempertimbangkan testing. Siapkan struktur yang mudah diuji menggunakan: - Unit Testing - Integration Testing - API Testing - End-to-End Testing - Playwright Skenario penting: 1. Create Sales Order 2. Create Purchase Order 3. Goods Receipt 4. Delivery Order 5. Sales Invoice 6. Purchase Invoice 7. Customer Payment 8. Supplier Payment 9. Stock Update 10. Automatic Journal 11. Retur 12. Permission 13. Duplicate Transaction Prevention 14. Period Closing Pastikan business logic dapat diuji tanpa bergantung sepenuhnya pada UI. ================================================== 17. URUTAN PENGEMBANGAN ================================================== Jangan membangun seluruh sistem sekaligus tanpa validasi. Gunakan tahapan berikut: FASE 1: - Authentication - Role & Permission - Company Settings - Master Data - Chart of Accounts FASE 2: - Inventory Foundation - Opening Stock - Inventory Movement - Warehouse FASE 3: - Purchase Order - Goods Receipt - Purchase Invoice - Supplier Payment FASE 4: - Sales Order - Delivery Order - Sales Invoice - Customer Payment FASE 5: - Automatic Journal - Piutang - Hutang - General Ledger FASE 6: - Financial Reports - Inventory Reports - Sales Reports - Purchase Reports FASE 7: - Audit Trail - Advanced Validation - Testing - Performance Improvement Setelah setiap fase selesai: - Verifikasi database - Verifikasi relasi - Verifikasi business logic - Verifikasi permission - Uji alur transaksi - Periksa error handling ================================================== 18. ATURAN IMPLEMENTASI LOVABLE ================================================== Prioritaskan kualitas dan integritas data dibandingkan sekadar menambahkan banyak halaman. Jika terdapat kebutuhan yang belum didefinisikan: - Gunakan asumsi bisnis yang masuk akal - Dokumentasikan asumsi tersebut - Hindari implementasi yang mengubah data secara diam-diam - Jangan membuat fitur pajak kompleks sebelum konfigurasi pajak ditentukan - Jangan menganggap semua transaksi langsung lunas - Jangan menganggap penerimaan barang selalu sama dengan invoice - Jangan menghapus data transaksi secara sembarangan Jika ada batasan teknis platform, jelaskan batasannya dan implementasikan alternatif yang aman. Mulai dengan membangun: 1. Database schema 2. Authentication 3. Master Data 4. Inventory Foundation 5. Modul transaksi pertama Pastikan hasil akhir dapat dikembangkan secara bertahap menjadi ERP yang lebih lengkap. ================================================== HASIL YANG DIHARAPKAN ================================================== Saya ingin mendapatkan aplikasi ERP berbasis web yang: - Profesional - Responsif - Memiliki database nyata - Memiliki modul terintegrasi - Memiliki business logic yang jelas - Memiliki accounting double-entry - Memiliki inventory tracking - Memiliki laporan yang konsisten - Memiliki role dan permission - Memiliki audit trail - Mudah dikembangkan - Mudah diuji oleh QA
